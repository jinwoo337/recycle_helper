# 운영 사이트 점검 결과 (2026-10-26)

## 발견 및 수정

1. **비정상 해시 주소의 페이지 처리 오류**: 운영 주소 `#toString`에서 제목이 `undefined`로 바뀌고 `TypeError: route.render is not a function`이 발생했습니다. 라우트 객체의 상속 속성까지 검색했기 때문입니다. `src/app.js`에서 `Object.hasOwn`으로 실제 등록된 주소만 허용하도록 수정했습니다. 수정 후 별도 로컬 주소에서 같은 해시 접속 시 홈으로 복구되는 것을 확인했습니다.
2. **운영 DB 추가 설정 미반영**: 개인정보를 읽지 않는 HEAD 요청으로 `disposal_favorites`, `disposal_feedback`가 각각 404인 것을 확인했습니다. 공개 품목 조회에서도 `catalog-022` 음식물 그룹이 없었습니다. 운영 화면의 사과껍질 예시에서도 자동 재질 입력이 되지 않는 것을 재현했습니다. 코드 배포만으로 해결되지 않으며, Supabase 관리자가 `supabase/improvements.sql`을 실행해야 합니다. 이번 점검에서 DB를 수정하거나 관리자 권한을 우회하지 않았습니다.

## 실제 확인한 범위

- 운영 사이트: 메인 표시, 메인 예시→입력 전달, 회원가입 빈 입력 시 항목별 오류와 첫 오류 포커스, 잘못된 로그인에 대한 실제 Supabase 응답·안내·버튼 복구·비밀번호 비우기.
- 기존 사용자 브라우저 기록과 분리된 로컬 5188 주소: 우유팩 자동 입력, 오염 없음·결합 없음 조건의 종이팩 판별, 비회원 기록 저장, 새로고침 후 복원, 총 1개/종이팩 100% 통계, 결과 복사, 비회원 즐겨찾기 저장, 유형 필터와 전체 통계 유지, 삭제 전 확인·취소.
- 모바일 390×844 기록 화면: DOM 가로폭 375px/스크롤폭 375px로 가로 넘침 없음. 화면 이미지도 확인했습니다. 물리 기기를 사용한 검증은 아닙니다.
- 자동 테스트 59개 통과: 조건별 판별 7,680개 조합, 데이터 저장소, 인증 대역, 지역별 규칙, PostgreSQL/PGlite RLS와 계정 간 격리 등을 포함합니다. 운영 DB에 실제 회원 A/B를 생성하여 권한을 재시험한 결과는 아닙니다.

## 미검증과 남은 항목

- 실제 정상 회원의 가입·메일 인증·로그인·로그아웃, 마이페이지의 실제 Supabase 저장·다른 기기 복원은 이번 점검에서 실행하지 않았습니다.
- 회원 즐겨찾기·제보·추가 음식물 품목 및 음식물 통계는 SQL 반영 후 실계정 검증이 필요합니다. 비회원 즐겨찾기 동작과 구분합니다.
- 브라우저에서 기존 사용자 기록을 삭제하지 않았습니다. 삭제 실행·통계 반영은 자동 테스트에서 검증하고, 실제 화면은 확인창과 취소까지 점검했습니다.
- 지역 안내는 공식 자료를 확인한 지역·품목만 적용합니다. 전국 모든 품목·동별 일정의 현장 정확성을 검증한 것은 아닙니다.
