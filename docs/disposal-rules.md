# 3회차 분리배출 판별 설계

## 파일과 역할

- `src/pages/item-input/item-input.js`: 기존 입력 화면 확장, 조건부 질문, 부속품 추가/삭제, 결과 표시, 과거 결과 복원.
- `src/domain/disposal/rules.js`: 화면이나 저장소에 의존하지 않는 순수 판별 함수, 재질/세부 종류 선택지, 조건 정규화, 기준 버전.
- `src/services/disposal-history.js`: 결과 저장·조회 및 브라우저 저장소 구현. 기존 `recent-items.js`와 v1 데이터는 그대로 유지.
- `src/styles/item-input.css`: 기존 색상과 카드 스타일을 활용한 결과/부속품/기록 스타일.
- `src/pages/main/main.js`: 판별 기능이 준비 중이라는 문구 갱신.
- `package.json`, `tests/disposal.test.js`, `tests/disposal-history.test.js`: 실행 및 핵심 규칙/기록 검증. 기존 인증/최근 이름 테스트도 실행.

## 판별 순서

1. 사용자가 재질과 세부 종류를 선택합니다. 물품 이름으로 재질을 추측하지 않습니다. 이름은 위험·특수 품목을 놓치지 않기 위한 추가 확인 신호로만 사용합니다.
2. 지원 대상인지 확인합니다. 알 수 없는 재질, 특수 유리·가스 용기·일반 수거 대상인지 불명확한 제품은 확정하지 않습니다. 종이의 감열지·분리되지 않는 코팅 등 명시적인 제외 품목은 일반 배출로 안내합니다.
3. 현재 오염을 확인합니다. 세척 이력만으로 깨끗하다고 판단하지 않습니다. 오염이 남았으나 제거 가능하면 **제거 완료 후** 재활용을 안내합니다. 제거 불가능한 종이/플라스틱/비닐/스티로폼은 일반 배출, 유리·캔은 내용물과 지역 기준의 추가 확인을 안내합니다.
4. 다른 재질이 결합되어 있는지 확인합니다. 결합 여부 불명 또는 분리 불가이면 복합재질의 수거 기준을 추가 확인하도록 합니다. 복합재질을 일괄적으로 일반쓰레기로 확정하지 않습니다.
5. 분리 가능한 부속품은 각각 재질·세부 종류·오염 상태를 적용합니다. 본체와 부속품 중 확인이 필요한 것이 있으면 전체 결과에도 표시합니다. 일부는 재활용, 일부는 일반 배출인 경우 재질별 안내를 제공합니다.

`normalizePart`는 숨겨진 세척/오염 제거 답변을 삭제합니다. 화면은 숨긴 질문의 required를 해제하고 disabled 처리하며, 다시 보이면 답변을 새로 받습니다. 일반 종이는 물 세척을 요구하지 않습니다. 종이팩과 종이컵의 준비 과정은 별도 규칙으로 안내합니다.

## 결과 예시

| 입력 | 결과 |
| --- | --- |
| 일반 플라스틱 용기, 깨끗함, 단일 재질 | 플라스틱류 |
| 같은 용기, 세척했으나 오염 남음, 제거 불가 | 종량제봉투 |
| 같은 용기, 오염 제거 가능 | 오염 제거 후 플라스틱류 |
| 무색 투명 생수·음료 페트병 | 투명 페트병 별도 수거 |
| 유색/다른 용도 페트병 | 플라스틱류 |
| 일반 종이 / 우유팩 | 종이류 / 종이팩 구분 |
| 깨끗한 플라스틱 본체 + 분리 가능한 오염된 종이 부속품 | 본체 재활용, 제거 불가 오염 종이는 일반 배출 |
| 결합 재질 분리 불가 / 오염 제거 가능 여부 모름 | 추가 확인 필요 |

## 근거와 적용 범위

확인일: 2026-10-08. 규칙 버전: `2026-10-08.v1`.

- [분리의정석: 재활용가능자원의 분리수거 등에 관한 지침](https://wasteguide.or.kr/front/bbsList.do?bbsId=BBS_0003) — 2026-01-01 시행 지침의 품목별 일반 수거 요령.
- [한국환경공단: 분리배출표시제도](https://www.keco.or.kr/web/lay1/S1T183C1049/contents.do) — 표시와 복합재질 구분 확인.
- [한국소비자원: 재질별 분리배출](https://www.kca.go.kr/smartconsumer/sub.do?menukey=7740) — 오염·다른 재질 제거 및 일반 수거 제외 품목 참고.

전국 공통 요령을 참고한 구현이며 모든 품목과 지역을 포괄하지 않습니다. 지역별 수거함, 배출일, 특수규격마대, 대형폐기물 여부는 자동 판별하지 않습니다. 특수 제품, 부속품 내부 복합재질 및 위험한 내용물은 지역 안내를 확인해야 합니다. 결과 화면에도 적용 한계와 출처 링크를 표시합니다. 사용자가 선택한 재질·상태가 정확하다는 조건에서 작동합니다.

## 기록과 다음 회차

저장 키: `recycle-helper.disposal-history.v2.<회원 ID 또는 guest>`.

각 기록은 `{ schemaVersion: 2, id, itemName, createdAt, input, result }`입니다. `input`에 정규화한 조건과 부속품 배열을, `result`에 최종 안내·사전 처리·이유·재질별 결과·규칙 버전을 저장합니다. 최근 결과 조회 시 현재 규칙으로 재계산하지 않고 당시 결과를 표시합니다. 조건 복원 후 새로 제출하면 현재 규칙으로 새 기록을 만듭니다.

`localHistoryRepository.list()`와 `save(record)`는 Promise를 반환합니다. 다음 회차에는 인증된 회원 ID, DB 테이블과 RLS를 설계하고 같은 인터페이스의 Supabase 저장소를 구현해 주입할 수 있습니다. 현재 로컬 회원 ID는 서버 접근 권한으로 사용할 수 없습니다. 브라우저 저장소가 차단/초과된 경우 결과는 화면에서 확인할 수 있고 저장 실패를 명시합니다. 손상된 기록은 무시하며 기존 v1 이름 데이터는 삭제하지 않습니다.
