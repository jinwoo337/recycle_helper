# 2026-10-28 웹사이트 개선 기록

이전 UI 점검 수정에 이어 사용량 한도 안에서 개선했다. 2026-10-28 사용자 요청으로 아래 변경을 커밋·배포 대상으로 정리했다. 이 문서는 배포 전 검증 기록이며, 운영 반영 여부는 배포 완료 결과에서 확인한다. 기존 `.claude/` 폴더와 운영 계정 데이터는 수정하지 않았다.

## 입력과 분류

- 홈 검색·가이드·기록에서 이름만 전달해도 직접 입력할 때와 같은 종류 인식을 사용한다.
- 미등록 물건을 재질만 보고 포장재로 간주하던 처리를 제거했다. 포장재·음식물·모르겠음 간편 선택과 세부 종류 선택을 제공한다. 재질을 모르는 포장재도 임의의 재질을 고르지 않고 확인 안내로 진행할 수 있다.
- 자동 인식인지 직접 선택인지 기록한다. ‘다른 물건이에요’로 거절한 인식은 다시 적용하지 않는다. 이전 자동 선택은 현재 인식으로 갱신하되 직접 선택은 보존한다.
- ‘부푼 AA 건전지’, ‘리튬이온배터리 누액’처럼 손상 표현과 전지 이름이 떨어져 있어도 기존 손상 전지 안내를 선택한다. 포장·케이스는 본체로 단정하지 않는다.
- AI를 껐을 때 이전 추정을 새 입력에 사용하지 않는다. 기본 판별은 AI·원격 품목 조회를 기다리지 않는다. AI는 별도 참고 의견으로 표시한다.
- 지연된 품목 조회가 작성 중인 조건을 초기화하지 않도록 보호하고, 실패 시 입력을 유지하는 재시도 버튼을 제공한다.
- 판별 저장을 중복 실행하지 않고 화면 이동·입력 변경 뒤 늦은 응답이 현재 입력 상태를 덮지 않도록 했다.
- 규칙 버전은 `2026-10-28.v11`. 이전 기록은 원본을 보존하며 현재 기준으로 재확인해 표시·복사한다.

## 검색 성능과 데이터 보존

- 이름과 별칭을 매번 전체 순회하지 않고 품목 갱신 시 색인을 구성한다.
- DB 조회의 오래된 재질이 검토한 전용 수거 경로를 가리지 않는 기존 우선순위를 유지한다.
- 같은 이름에 서로 다른 DB 재질·종류가 있으면 이전의 정상 색인을 유지하고 오류를 알린다. 조회 결과나 원래 DB 배열을 수정해도 다음 조회의 원본을 바꾸지 않는다.
- AI 별칭 정리에서 공백 대신 영문 `s`를 삭제하던 정규식 오류를 수정했다.

같은 로컬 Node 환경의 단일 비교 측정:

| 작업 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 알려진 이름·없는 이름 조회 10,000회 | 3,276ms | 31ms |
| ‘유’ 추천 검색 1,000회 | 1,176ms | 110ms |

이 수치는 해당 실행 환경의 측정이며 모든 기기의 응답 속도를 보증하지 않는다.

## 화면과 기록

- 홈과 입력 화면이 같은 자동완성을 사용한다. 방향키·Enter·Escape·조합 완료·바깥 클릭의 닫힘을 통일하고 화면별 선택지 ID와 이벤트 정리를 분리했다.
- 모바일 홈의 추천 목록은 검색 버튼을 덮지 않고 입력란 아래에 펼쳐진다.
- 선택한 임시 지역을 탭 안에서 이동·새로고침 후에도 유지한다. 회원·비회원·다른 회원의 선택을 분리하며, 프로필 기본 지역이 바뀌면 새 기본값을 우선한다.
- 기록 검색에 표기·별칭 정규화를 적용했다. 날짜 범위 오류는 빈 검색 결과와 구분하고, 필터 변경 시 이전 삭제 확인을 닫는다.
- 즐겨찾기 저장 중 읽기 응답이 버튼을 다시 활성화하지 않도록 했다. 늦은 이전 조회와 중복 클릭을 차단한다.
- 제보는 앞뒤 공백을 제외한 길이를 확인하고, 전송 중 중복 전송이나 초안 변경을 막으며 실패 시 다시 입력할 수 있게 한다.

## 비밀번호 복구

- 로그인에서 재설정 메일 요청 화면으로 이동한다. 계정 존재 여부를 단정하지 않는 완료 안내와 같은 브라우저에서 링크를 여는 안내를 제공한다.
- Supabase의 `PASSWORD_RECOVERY` 인증을 확인한 현재 계정에만 새 비밀번호 입력을 제공한다. 복구 상태는 계정과 탭을 구분하고 15분 후 만료된다.
- 초기 인증 이벤트를 세션 조회 전에 등록하고, 오래된 초기화 응답이나 이전 세션 스냅샷이 나중의 인증 상태를 덮지 않게 했다.
- 복구 인증 없는 직접 접근, 계정 변경, 만료, 같은 비밀번호, 요청 제한을 구분한다. 새 비밀번호는 브라우저 저장소에 보관하지 않으며 요청 완료 후 입력란에서 지운다.
- 인증 콜백 처리 후 주소에 코드·토큰·오류 원문을 남기지 않는다. Google 로그인과 일반 안내 링크는 유지한다.

근거: [Supabase 재설정 메일 API](https://supabase.com/docs/reference/javascript/auth-resetpasswordforemail), [사용자 비밀번호 갱신 API](https://supabase.com/docs/reference/javascript/auth-updateuser).

추가 SQL은 없다. 실제 메일은 Supabase 메일 발송·허용 복귀 URL 설정에 영향을 받는다. 실제 계정에 메일을 보내거나 비밀번호를 변경하지 않았으므로, 실제 메일 수신·링크 복귀는 운영 전 확인이 필요하다. 서비스 로직은 인증 테스트 대역으로 검증했다.

## 검증과 범위

- 전체 자동 테스트 161개 통과. 재질·상태 7,680개 조합, PostgreSQL 권한·기록·게임, 기존 인증·Google 로그인 및 새 회귀 검증을 포함한다.
- 이후 인증 상태 확인 가드와 복구 안내 문구 변경에 대한 관련 테스트 12개 통과.
- `git diff --check` 통과.
- 실제 로컬 브라우저에서 홈 자동완성 선택→상태 입력, 종류 선택·모름·인식 거절, 지역 이동·새로고침 유지, 날짜 오류와 초기화, 복구 진입·빈 이메일 검증·인증 없는 직접 접근을 확인했다.
- 운영 계정의 기록·프로필·랭킹·비밀번호는 변경하지 않았다. 제보와 복구 메일은 실제 전송하지 않았다.
- 실제 Windows 한글 IME와 실기기 모바일, 모든 지자체·실물 품목의 현장 정확성을 확인한 것은 아니다.
