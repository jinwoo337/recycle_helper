# 설명·사진으로 분리배출 안내 받기

## 이용 방법

홈과 물건 입력 화면에서 찾기 방식을 선택한다.

- 이름으로 찾기 (`#/item-input`): 기존 이름·종류·상태 기반 판별과 선택적인 AI 분류 의견을 유지한다.
- 물건 설명하기 (`#/describe`): 10~2,000자의 설명을 보내 AI가 물건의 특징, 배출 방법과 순서, 주의사항, 추가 질문을 작성한다.
- 사진으로 인식하기 (`#/photo`): 모바일 촬영 또는 저장된 사진 선택, 미리보기와 선택적인 설명을 제공한다. 물건 전체와 분리배출 표시 모두 입력할 수 있다. 실제 카메라 실행 방식은 기기·브라우저에 따라 다르며 저장된 사진으로도 이용할 수 있다.

새 모드의 결과는 AI 참고 안내로 표시한다. 인식 확실성이 낮으면 구체적인 배출 순서를 숨기고 확인 질문을 보여준다. 인식한 물건 이름으로 기존 기준 입력 화면을 다시 열 수 있으나, AI가 추정한 재질·오염·종류를 확인된 사용자 답변처럼 넘기지 않는다. 지자체 기준을 실시간 조회하는 기능은 아니다.

## 전송과 보관

- 선택한 사진은 안내 버튼을 누르기 전까지 브라우저에서만 처리한다.
- JPG·PNG·WebP, 원본 12MB 이하를 지원한다. 브라우저에서 최대 긴 변 1,440픽셀로 다시 그려 JPEG로 전송한다. 원본 EXIF 촬영 위치 등 메타데이터를 전달하지 않는다. HEIC는 JPG 변환을 안내한다.
- 서버에는 `POST /api/assist`의 JSON 본문으로 설명, 정규화한 지역, 선택한 경우 압축 사진을 보낸다. 본문을 URL에 넣지 않는다. 키는 기존 `GEMINI_API_KEY`를 서버에서만 사용한다.
- 설명·사진·새 안내는 기존 이름별 캐시, 공용 AI 추정 저장소, 개인 판별 기록에 자동 저장하지 않는다. 응답은 `Cache-Control: no-store`이다. 공급자 원문 오류에 입력이 섞일 수 있어 오류 상태만 로그에 기록한다.
- 사진과 설명은 분석을 위해 Google Gemini에 전달된다. 이 사이트의 미보관 정책이 공급자 측 데이터 처리 정책을 대신하지 않는다.

## 처리와 검증

- 서버에서 모드·설명 길이·지역·이미지 형식과 용량·파일 시그니처를 검사한다. 이미지 URL이나 SVG는 받지 않는다.
- 구조화된 응답을 서버·브라우저 양쪽에서 검증한다. 생성된 문자열은 HTML로 실행하지 않고 이스케이프한다.
- 기존 AI 요청 제한과 사용 가능한 모델 선택을 공유하되, 설명·사진 요청은 공용 품목 분류와 별도로 실행한다. 기본 모델 오류에는 예비 모델을 사용한다.
- 전송 중 중복 실행을 막고, 분석 취소·화면 이동 후 늦은 응답이 현재 화면을 바꾸지 않도록 한다. 실패해도 현재 설명·사진은 유지한다. 사진 교체·삭제 뒤 늦은 압축 완료가 이전 사진을 복원하지 않도록 한다.
- 자동 테스트는 실제 Gemini 호출 없이 가짜 공급자 응답으로 입력·응답 검증, 이미지 전달, 예비 모델, 오류, 취소·중복·늦은 응답을 확인한다. 로컬 브라우저에서는 설명 제출 실패 후 입력 유지, 사진 선택·JPEG 변환·미리보기·삭제·미선택 제출, 390px 화면 넘침을 확인했다. 실제 스마트폰 카메라 하드웨어는 시험하지 않았다.

## 운영 확인 (2026-10-28)

전체 자동 테스트 178개가 통과했다. 운영 API에서 개인정보 없는 알약 설명과 자체 제작 재질 표시 이미지를 각각 전송해 HTTP 200 응답을 확인했다. 이미지의 `몸체 PP`와 `뚜껑 HDPE`를 따로 읽었고, 실제 물건 사진이 아니므로 인식 확실성을 낮게 표시하고 배출 순서를 숨기는 것을 확인했다. 실제 응답 점검에서 알약 설명에 다른 약 형태 안내가 섞이고 포장 처리 방법을 일률적으로 말하는 문제가 보여, 해당 물건만 안내하고 약 포장 처리 방법은 수거처마다 확인하도록 지시문을 보완했다. 이 시험은 모든 물건·사진의 인식 정확도를 보장하지 않는다.
