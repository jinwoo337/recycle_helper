# 첫 방문 흐름과 UI 간소화 검토 (2026-10-26)

## 발견한 불편

- 가입·로그인 화면에 큰 소개 영역과 반복 안내가 먼저 나와, 실제 입력까지 스크롤이 길었습니다.
- 물건을 입력하지 않은 상태에서도 자동 입력 설정·재질 선택·보조 기록 메뉴가 나타나 시작점이 분산됐습니다.
- 알려진 품목도 자동으로 채워진 재질·세부 종류를 계속 읽어야 했고, 깨끗한 단일 물품에도 오염과 결합 질문을 각각 선택해야 했습니다.
- 결과 화면에서 배출 방법·처리 단계·단일 재질 설명이 반복되어 가장 중요한 행동을 찾기 어려웠습니다.
- 기록 화면에 0개인 통계 항목과 날짜·유형·정렬 입력이 항상 나와, 기록이 적은 신규 회원에게 과밀했습니다.
- 즐겨찾기 저장 직후 자동 화면 갱신이 선택 상태를 먼저 바꿔, 실제로 저장됐지만 ‘해제했어요’라고 안내하는 오류를 재현했습니다.

## 실제 변경

| 흐름 | 변경 |
| --- | --- |
| 메인 | 가입 없이 먼저 판별할 수 있음을 검색창 아래 안내. 예시는 등록된 우유팩·투명생수병·과자봉지로 정리. 기존 초록색 디자인과 분리수거함 일러스트 유지 |
| 가입·로그인 | 소개 영역을 없애고 한 카드에서 Google 또는 이메일 선택. 안내는 펼쳐보기로 정리. 비밀번호 보기·숨기기와 가입 없이 사용하기 링크 추가 |
| 지역 | 대전·서울 구는 드롭다운으로 선택. 세종은 불필요한 구 입력 생략. 다른 지역은 시·군·구 직접 입력 유지. 지역 지원 범위는 펼쳐보기로 보존 |
| 이름 입력 | 처음에는 이름·추천 예시부터 표시. 품목을 고르면 상태 질문이 나타남. 확인된 재질은 요약으로 접고 직접 수정 가능 |
| 빠른 판별 | 등록된 품목과 재질·종류가 맞을 때 ‘깨끗하고 다른 재질도 없어요 → 결과 보기’ 제공. 사용자가 이 상태를 명시적으로 확인해야 작동하며 자동 추측하지 않음 |
| 예외 입력 | 생수병의 색상·용도 등 모호한 종류는 선택을 요구. 오염·결합·모르겠음 답변에는 빠른 버튼을 숨기고 추가 질문·부속품 입력 유지 |
| 결과 | 최종 분류와 배출 순서를 먼저 표시. 이유·지역 근거·출처·입력 조건은 펼쳐보기로 보존. 복합 물품의 본체·부속품별 처리는 계속 보이게 유지 |
| 기록·즐겨찾기 | 입력 화면에서는 한 보조 메뉴에 접어두고 열었을 때 조회. 기록 화면의 유형·기간·정렬은 접고 현재 적용 개수 표시. 통계는 1개 이상인 유형만 그림으로 표시하되 집계와 필터 항목은 유지 |
| 안내 | 요청하지 않은 즐겨찾기 조회 실패가 판별 결과를 먼저 가리지 않도록 함. 사용자가 즐겨찾기를 누르면 실패 원인을 안내. 저장·해제 성공 문구 오류 수정 |
| 인증 복귀 | 성공 안내를 오류처럼 새로고침시키지 않고 닫을 수 있게 정리. 오류에는 새로고침·닫기 제공 |

## 첫 방문자가 사용할 흐름

1. 메인에서 이름을 입력하거나 예시를 고릅니다. 회원가입 없이 기본 판별을 이용할 수 있습니다.
2. 자동으로 표시된 재질이 맞는지 확인합니다. 맞지 않으면 재질 요약을 열어 수정합니다. 정보가 모호하면 종류를 직접 선택합니다.
3. 현재 오염·결합 상태를 답합니다. 깨끗하고 부속 재질이 전혀 없으면 빠른 버튼 한 번으로 결과를 볼 수 있습니다.
4. 결과의 최종 배출 분류와 순서를 확인합니다. 세부 근거·출처·조건은 필요할 때 펼칩니다.
5. 지역과 기록을 계정에 보관하려면 Google 또는 이메일로 로그인합니다. Google 신규 회원은 기존 연결 흐름에 따라 마이페이지에서 지역을 저장합니다.

## 검증

- 자동 테스트 67개 통과. 기존 인증·Google OAuth·판별 7,680개 조합·DB/RLS·회원 기록 테스트를 유지하고, 빠른 판별의 조건 전달·이전 오염/부속품 답변 제거·원본 보존·미등록/특수/충돌 품목 차단·수동 입력과 동일 결과를 추가 확인했습니다.
- 별도 로컬 5190 주소에서 ‘우유팩 선택 → 깨끗한 단일 재질 확인’ 두 번의 클릭으로 판별과 비회원 저장을 확인했습니다. 이는 해당 상태에 맞는 품목의 예시이며 모든 물품에 두 번으로 충분하다는 뜻은 아닙니다.
- 모호한 생수병은 종류 선택이 필요하고 빠른 버튼이 나오지 않음을 확인했습니다. 오염·세척·제거 가능 여부·분리 가능한 플라스틱 부속품 입력과 재질별 결과도 확인했습니다.
- 결과 저장·과거 결과 조회·비회원 즐겨찾기 저장/해제 양쪽 문구·접힌 기록 메뉴·필터 적용 개수·필터 초기화·전체 통계 유지와 브라우저 오류 로그를 확인했습니다.
- 가입 화면에서 대전 유성구·서울 관악구 선택, 세종 구 입력 생략, 동적으로 바뀐 구 입력의 검증, 비밀번호 보기, 빈 입력의 항목별 오류를 확인했습니다. 실제 신규 계정은 만들지 않았습니다.
- 휴대전화 390×844, 태블릿 768×1024, PC 1440×1000에서 입력·기록 화면 가로 넘침이 없음을 확인했습니다. 휴대전화 가입·결과 화면과 PC 입력 화면도 이미지로 확인했습니다. 물리 기기 테스트는 아닙니다.
- 실제 기존 회원의 운영 기록을 추가·삭제하거나 닉네임·지역을 바꾸지 않았습니다. 이메일/Google 로그인과 실제 계정 분리는 직전 작업에서 검증했으며, 이번 UI 변경 후 새 계정 생성·Google 동의 절차를 다시 실행한 것은 아닙니다.

## 유지·남은 범위

판별 규칙, Supabase 인증 방식·RLS·테이블, 기존 사용자 데이터는 변경하지 않았습니다. 이번 변경에 추가 SQL은 없습니다. 기존 회원 즐겨찾기·제보·추가 음식물 카탈로그의 DB 설정 필요 여부는 별도로 관리합니다. 전국 모든 지역·물품의 판별 정확성, SMTP 전달 문제, 비밀번호 재설정은 이번 UI 작업으로 해결됐다고 주장하지 않습니다.

실제 처음 방문자를 모집한 사용성 테스트는 하지 않았습니다. 이번 검토는 코드 검토와 브라우저 시나리오 점검이며, 다양한 연령·디지털 숙련도의 사용자가 쉽게 사용하는지에 대한 현장 검증은 남아 있습니다.
