# 분리배출 안내 개선 계획

운영 버전 `9ac4b18` 기준 · 2026-11-14

버리기 직전에 **어디에 버리는지 → 지금 무엇을 해야 하는지 → 왜 그렇게 해야 하는지**를 한 화면에서 확인할 수 있게 한다.

## 1. ‘지금 할 일’ 바로 아래에 이유 표시

현재 이름 검색 결과의 이유는 접힌 ‘판단 근거·지역 기준’ 안에 있다. 결과 화면의 **‘지금 할 일’에 표시되는 배출 단계와 부속품 안내가 끝난 직후**에 **‘왜 이렇게 버리나요?’**를 펼쳐진 상태로 배치한다. 재질·오염·부속품·지역 중 실제 판정을 바꾼 이유를 1~2문장으로 보여 준다.

| 결과 예시 | 이유 문구 초안 |
| --- | --- |
| 감열 영수증 | 감열지는 일반 종이류 재활용 수거 대상에서 제외돼요. |
| 깨끗한 우유팩 | 종이팩은 일반 종이와 다른 방식으로 수거해요. |
| 재질이 확인되지 않은 아이스팩 | 물과 젤은 처리 방법이 달라요. 팩에 적힌 내용물을 확인해야 배출 방법을 정할 수 있어요. |
| 본체는 판별했고 부속품은 확인이 남음 | 본체와 라벨은 재질별로 배출 방법이 달라요. 라벨의 재질을 확인하면 라벨 안내도 볼 수 있어요. |

- 이름·설명·사진에서 판별한 결과와 저장된 기록 상세에 같은 순서와 표현을 적용한다. 복사한 결과에도 배출 단계 다음에 같은 이유가 들어간다.
- 조건이 부족하면 어떤 정보가 부족하고 그 정보가 왜 필요한지 설명한다. 아직 물건 이름을 확인 중이면 그 이유만 보여 준다.
- 배출 방법과 이유는 같은 판정에서 가져온다. 적용된 지역 규칙이 결과를 바꾸면 이유도 함께 갱신한다. 상세 출처와 확인일은 ‘판단 근거·지역 기준’에서 볼 수 있게 한다.

## 2. 판별 알고리즘 개선 순서

| 순서 | 수정할 사항 | 확인할 동작 |
| --- | --- | --- |
| 1 | **지역 규칙과 결과의 이유를 일치시킨다.** 깨진 유리의 지역 규칙 적용 여부를 사용자에게 표시되는 이유 문장에 의존하는 코드를 점검한다. 서울 비닐의 자국·고형물 분기에서 결과, 이유, 다음 질문이 함께 갱신되는지도 확인한다. | 서울 비닐에서 기름 자국만 있는 경우와 고형물이 남은 경우에 각각 다른 안내가 나온다. 같은 깨진 유리도 지역을 바꾸면 해당 지역 근거에 맞춰 안내와 이유가 함께 바뀐다. |
| 2 | **조건이 부족한 결과에서 필요한 질문으로 바로 돌아간다.** 부속품의 이름과 재질이 충돌하거나 오염을 확인하지 못했을 때 해당 항목에 초점을 맞춘다. 사용자가 이미 답한 본체와 다른 부속품의 조건은 유지한다. | 라벨만 재질 미확인이면 라벨 입력으로 바로 이동한다. 분리 가능하다고 확인한 경우에만 확인이 끝난 부분의 배출처를 먼저 보여 준다. |
| 3 | **미등록 이름의 후보를 더 정확하게 찾는다.** 표현·띄어쓰기 차이는 같은 품목으로 묶고, 오타와 여러 해석이 가능한 이름은 서로 구분할 수 있는 후보를 앞에 둔다. 부속품이 달린 등록 품목명과 여러 개를 따로 버리는 입력도 비교한다. | ‘생수병 뚜껑’에는 뚜껑 후보가 먼저 나온다. ‘과자봉지랑 우유팩’은 각각 판별할 수 있고, 등록된 ‘종이컵과 플라스틱 뚜껑’은 한 물건의 구성으로 유지된다. |
| 4 | **이름·설명·사진에서 확인한 정보가 이어지게 한다.** 사진에서 직접 확인한 표시와 부위를 입력 화면으로 넘기고, 재질 코드만 확인했으면 아직 필요한 용도·형태만 묻는다. | 같은 물건·지역·조건이면 입력 방식에 관계없이 결과와 이유가 같다. 본체에서 ‘무색페트’를 확인한 경우와 일반 ‘PET’ 코드만 확인한 경우에 필요한 질문이 다르다. |

## 3. 확인과 배포

1. 이유 표시와 알고리즘 수정은 위 순서대로 진행한다. 각 변경 뒤에는 해당 사례와 기존 검색 흐름을 확인한다.
2. 5시간 사용량을 작업 중 확인한다. 잔여 10%를 마감 기준으로 삼고, 최종 테스트와 운영 확인 시간을 남겨 기능 추가를 마친다. 한도가 가까우면 검증을 마친 변경까지만 배포한다.
3. 전체 자동 테스트와 Chrome·WebKit에서 ‘지금 할 일 → 왜 이렇게 버리나요?’의 순서, 짧은 검색, 지역 변경, 부속품 수정, 이전 기록을 확인한다. 사진은 확인된 표시를 넘기는 동작과 실제 인식 서비스 응답을 구분해 검증 결과를 기록한다.
4. 확인을 마친 변경을 운영에 배포한다. 운영 주소에서 새 버전이 제공되는지 확인하고, 우유팩·영수증·미등록 품목을 검색해 이유와 다음 행동을 다시 확인한다.
