# 전체 기능 점검 및 개선 보고서

점검일: 2026-10-26 (한국 시간). HTML/CSS/JavaScript, 서비스 계층, 판별 규칙, Supabase SQL 및 기존 테스트를 점검했습니다. 프레임워크나 추가 라이브러리를 도입하지 않았습니다. 운영 데이터의 삭제·초기화는 하지 않았습니다.

## 발견한 문제와 수정 전후

| 문제와 원인 | 수정 후 |
| --- | --- |
| 시작 시 품목 DB 로딩을 await해 메인·인증 화면까지 함께 지연 | 인증 복원 후 화면을 먼저 표시하고 품목은 별도 로딩, 판별 전에는 품목 준비를 확인 |
| 인증 복원이 실패하면 null 회원을 비회원처럼 취급할 수 있음 | 인증 확인 실패와 실제 비회원을 구분, 미확인 상태의 데이터 쓰기는 거절하고 재시도 안내 |
| 많은 기록을 offset으로 읽는 동안 추가·삭제가 발생하면 중복·누락 가능 | 정렬된 마지막 시각과 ID를 기준으로 다음 기록을 조회 |
| 형식이 손상된 이전 기록의 UUID·빈 이름이 DB 이전 전체를 막을 수 있음 | 유효한 레코드만 이전, 원본 브라우저 데이터는 보존 |
| 같은 탭의 동시에 발생한 비회원 저장이 같은 이전 목록을 읽어 덮어쓸 수 있음 | 쓰기 순서를 직렬화하고 작업 중 계정 전환 확인 |
| 과거 결과의 재입력 버튼이 입력 조건 없이 새 화면으로 이동 | 회원 ID에 연결된 일회성 조건 전달, 오염·결합·부속품을 함께 복원 |
| 자동 재조회가 선택한 결과 상세를 다시 만들어 제보 초안을 잃을 수 있음 | 같은 결과 상세는 유지하고 삭제되었을 때만 해제 |
| DB 조회 실패 후 오류와 빈 목록이 혼동되고 재시도가 불편 | 로딩·조회 실패·빈 기록 상태 분리, 명시적인 다시 불러오기 버튼 |
| 네트워크 요청이 오래 대기 | Supabase 요청에 12초 중단 처리와 재시도 안내 |
| 결과에 늘 일반 품목 출처 링크를 표시 | 당시 결과가 사용하는 검증된 출처를 표시, 음식물류는 지역 안내 병기 |

## 추가·개선 기능

- 메인 빠른 품목 입력과 예시 버튼. 이름을 입력 화면으로 전달하며 정확히 알려진 재질·종류만 자동 입력합니다. 자동 입력을 끌 수 있습니다.
- 입력 조건 요약, 필요한 질문만 표시, 새로 입력, 과거 조건 복원. 오염 상태·물품 이름을 바꾸면 관련 상태가 다시 갱신됩니다.
- 기존 자동완성과 방향키·Enter·Escape 조작 유지. 택배박스/택배상자, PET병/페트병 등 등록된 유사 명칭만 연결하고 임의의 오타를 사실로 간주하지 않습니다.
- 배출 행동을 번호 순서로 표시, 판단 이유·재질별 처리·입력 조건·지역 주의사항 구분.
- 결과 복사. 클립보드 사용이 불가능하면 선택해서 직접 복사할 수 있는 읽기 전용 입력란을 제공합니다.
- 결과에서 즐겨찾기 저장·해제, 입력 화면에서 저장한 조건 복원. 회원은 DB에, 비회원은 별도 브라우저 키에 저장합니다.
- 기록 검색과 유형·한국 날짜 범위 필터, 최신/오래된/이름순 정렬, 필터 초기화. 통계는 필터와 무관하게 전체 기록 기준을 유지합니다.
- 결과 오류·미등록 품목 제보. 회원의 제보는 검토 대기 상태로 별도 저장하고, 일반 회원은 검토 완료 상태로 바꾸거나 공식 품목을 수정할 수 없습니다.
- 버튼의 최소 터치 영역, 줄바꿈, 입력란·여백, 반응형 필터, 키보드 포커스와 동작 줄이기 설정 지원.

## 판별 보완과 정확성의 한계

기존 플라스틱·페트·종이·유리·캔·비닐·스티로폼과 위험·복합 재질 규칙을 유지했습니다. 음식물류는 별도 모듈로 일부 확인 품목만 추가합니다. 단단한 뼈·껍데기·씨앗, 부드러운 음식물, 포함 물질을 모르는 음식물을 구분하며 이물질 분리 여부를 확인합니다.

근거는 [분리배출 지침](https://www.wasteguide.or.kr/front/bbsList.do?bbsId=BBS_0003), [금천구 음식물류 안내](https://geumcheon.go.kr/portal/contents.do?key=818), [서울시 음식물류 안내](https://news.seoul.go.kr/env/archives/1899?listPage=1)입니다. 일반 수거 판단과 별도로 거주지 지침을 우선 확인하도록 합니다. 자동 테스트가 통과했다는 것은 구현한 분기와 데이터 처리의 일관성 검증이며, 모든 제품·오염 상태·지자체의 행정적 정확성을 보증하지 않습니다. 위험물·미등록 물품은 임의로 배출 방법을 만들어내지 않습니다.

## DB 호환성과 운영 반영

기존 프로젝트는 `supabase/improvements.sql`을 SQL Editor에서 추가 실행합니다. 즐겨찾기·제보 테이블과 RLS, 음식물 4개 품목 묶음, 통계 함수 확장만 추가합니다. 기존 회원·기록·결과·생성된 category 컬럼은 삭제하거나 다시 쓰지 않습니다. 재실행 시 데이터가 유지되는지 PostgreSQL 테스트로 확인합니다.

신규 설치는 `supabase/setup.sql`에 기본 설정과 편의 기능을 모두 포함합니다. `scripts/build-database-setup.js`로 생성합니다. 제보의 공식 반영은 운영자가 검증한 뒤 별도로 품목 데이터를 수정하는 작업이며 이번 앱에는 관리자 승인 화면을 추가하지 않았습니다.

## 미검증·남은 사항

- 실제 회원의 신규 가입 메일 수신·인증 링크와 정상 로그인·실제 다른 기기 동기화는 이번 자동화에서 재실행하지 않았습니다. 인증 대역과 PostgreSQL 권한 테스트 결과와 구분합니다.
- 새 테이블의 실계정 저장·즐겨찾기·제보는 추가 SQL 반영 및 로그인 상태에서 최종 확인이 필요합니다. 관리자 로그인 정보나 실제 비밀번호를 코드·대화에 요구하지 않습니다.
- DB 장애·요청 취소·권한 오류는 대역/네트워크 단위 테스트로 검증하며 운영 DB를 일부러 중단하지 않습니다.
- 모든 지역·실물 품목·오염 상태에 대한 현장 검증, 관리자 제보 승인 UI, 실시간 구독 기반 다른 기기 화면 갱신은 범위에 포함하지 않습니다. 다른 기기에서는 조회·새로고침·화면 복귀 시 최신 DB 기록을 불러옵니다.
