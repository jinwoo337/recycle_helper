# 맞춤형 분리배출 도우미

물건과 상태를 입력하면 최종 분리배출 방법, 필요한 처리 과정, 판단 이유를 안내하는 웹서비스.

HTML/CSS/JavaScript로 만드는 웹 서비스입니다. 2회차에는 메인, 로그인, 회원가입 화면과 기본 프런트엔드 구조를 구현했습니다. 외부 프레임워크나 패키지 설치 없이 실행할 수 있습니다.

## 실행 방법

Node.js 18 이상이 설치된 환경에서 프로젝트 루트에서 실행합니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:5173 으로 접속합니다. 종료는 터미널에서 Ctrl+C를 누릅니다. JavaScript 모듈을 사용하므로 HTML 파일을 직접 여는 대신 HTTP 서버로 실행해야 합니다. VS Code Live Server로 루트의 `index.html`을 열어도 됩니다.

## 2회차 구현 범위

- 메인: 서비스 소개, 이용 단계, 준비 중인 기능 안내.
- 로그인: 입력 검증 후 테스트 회원의 이메일·비밀번호와 비교하여 성공 시 메인 화면으로 이동, 실패 시 오류 안내.
- 회원가입: 닉네임 2~20자, 이메일, 비밀번호 8자 이상 및 확인 값 검증.
- 공통 헤더·푸터, 반응형 스타일, 키보드 포커스, 입력 오류 안내.
- 해시 기반 화면 전환: `#/`, `#/login`, `#/signup`, `#/item-input`. 새로고침과 뒤로 가기를 지원합니다.
- 메인의 ‘분리배출 알아보기’에서 물건 및 상태 입력 화면으로 이동합니다. 물건 이름, 주요 재질, 오염·세척·결합 여부와 결합된 재질의 분리 가능 여부를 입력하고 내용을 확인·수정할 수 있습니다.
- 입력 내용을 확인하면 물건 이름이 브라우저에 저장되고 옆의 ‘최근 분리배출한 물품’ 목록에 표시됩니다. 최근 8개의 고유 이름을 보여주며 같은 이름을 다시 입력하면 맨 위로 이동합니다. 로그인한 회원과 비회원의 목록은 별도로 저장합니다. 이 목록은 입력 기록으로, 배출 완료나 배출 방법 판별을 의미하지 않습니다.

테스트 계정은 `demo@example.com` / `recycle1234`입니다. 이메일은 앞뒤 공백과 대소문자를 정리해 비교하고 비밀번호는 정확히 일치해야 합니다. 성공하면 메인 화면과 헤더에 테스트 로그인 상태를 표시합니다. `sessionStorage`에 테스트 회원 ID만 저장해 같은 탭에서 새로고침해도 유지하며, 로그아웃하면 삭제합니다. 저장소가 차단된 환경에서는 현재 페이지의 메모리에서만 유지합니다.

테스트 회원은 `src/services/auth.js`에 정의된 공개 예시입니다. 서버 계정 생성, 서버 인증, API, 데이터베이스는 구현하지 않았으며 이 로그인 상태는 접근 권한을 보호하지 않습니다. 입력한 비밀번호는 저장하거나 전송하지 않습니다. 회원가입 시 브라우저 localStorage에 닉네임, 이메일, 회원 ID, 무작위 salt와 PBKDF2 비밀번호 검증값을 저장합니다. 비밀번호 원문은 저장하지 않습니다. 가입 완료 후 로그인 화면으로 이동하며 등록한 계정으로 로그인할 수 있습니다. 이메일 중복을 거절하고 저장 실패 시 가입 완료로 안내하지 않습니다. 계정은 같은 브라우저·같은 주소에서 유지되며 브라우저 데이터를 삭제하면 사라집니다. 다른 기기에는 공유되지 않습니다. 물건 입력 화면은 구현했습니다. 입력 초안은 현재 페이지와 메인 화면을 오가는 동안 유지되며 새로고침하면 초기화됩니다. 분리배출 방법 판별, 기록·통계는 다음 구현 대상입니다. 글꼴은 Google Fonts를 사용하며 연결할 수 없으면 시스템 글꼴로 표시합니다.

로그인 로직 검증: `node --test tests/auth.test.js`

진입점은 `index.html`과 `src/app.js`입니다. 화면 코드는 기존 `src/pages` 하위에, 공통 화면 틀은 `src/layouts`, 폼 UI는 `src/components`, 입력 검증은 `src/utils`, 스타일은 `src/styles`에 배치했습니다. `scripts/serve.js`는 로컬 개발용 정적 서버입니다.

## 프로젝트 구조

```text
recycling-helper/
├── docs/                  # 요구사항과 향후 설계 문서
├── public/
│   ├── images/            # 정적 이미지
│   └── icons/             # 정적 아이콘
└── src/
    ├── pages/
    │   ├── login/         # 로그인
    │   ├── signup/        # 회원가입
    │   ├── main/          # 메인
    │   ├── item-input/    # 물건 및 상태 입력
    │   ├── result/        # 판별 결과
    │   ├── history/       # 나의 기록
    │   └── statistics/    # 나의 통계
    ├── components/        # 여러 화면에서 사용하는 UI
    ├── layouts/           # 공통 화면 틀
    ├── styles/            # 공통 스타일
    ├── services/          # 외부 API 및 데이터 접근
    ├── domain/
    │   └── disposal/      # 분리배출 판단 규칙과 처리 과정
    ├── types/             # 공통 데이터 구조
    └── utils/             # 범용 보조 함수
```

빈 폴더의 `.gitkeep`은 Git에 폴더를 보존하기 위한 파일입니다. 실제 코드를 추가할 때 제거해도 됩니다.

화면 폴더는 역할을 구분하기 위한 구조입니다. 기록과 통계는 필요하면 하나의 화면으로 묶을 수 있습니다. 백엔드와 데이터베이스 구조는 기술 스택 결정 후 추가합니다.

서비스 범위와 검토 사항은 [요구사항](docs/requirements.md)에 정리했습니다.
