# 맞춤형 분리배출 도우미

물건과 상태를 입력하면 최종 분리배출 방법, 필요한 처리 과정, 판단 이유를 안내하는 웹서비스.

HTML/CSS/JavaScript로 만드는 웹 서비스입니다. 기존 메인·로그인·회원가입 화면을 유지하며 3회차에 조건 기반 분리배출 판별과 결과 기록을 추가했습니다. 외부 프레임워크나 패키지 설치 없이 실행할 수 있습니다.

## 실행 방법

Node.js 18 이상이 설치된 환경에서 프로젝트 루트에서 실행합니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:5173 으로 접속합니다. 종료는 터미널에서 Ctrl+C를 누릅니다. JavaScript 모듈을 사용하므로 HTML 파일을 직접 여는 대신 HTTP 서버로 실행해야 합니다. VS Code Live Server로 루트의 `index.html`을 열어도 됩니다.

## 4회차: Supabase 실제 인증 (현재)

### 완성도 개선 (2026-10-26)

메인에서 바로 품목명을 입력할 수 있고, 관련 조건만 나타나는 입력 화면과 선택 조건 요약을 제공합니다. 결과 복사, 조건을 불러와 재판별, 회원별 즐겨찾기, 한국 날짜·유형별 기록 필터와 정렬, 검토 대기 제보를 추가했습니다. 새 SQL은 기존 회원·판별 기록을 삭제하지 않습니다.

기존 Supabase 프로젝트에는 **`supabase/improvements.sql`을 1회 실행**해야 회원 즐겨찾기·제보와 음식물류 품목/통계가 연결됩니다. 신규 프로젝트는 생성된 `supabase/setup.sql`로 전체를 설치합니다. 사용자 제보는 `disposal_feedback`에만 저장되며 공식 `disposal_items`에 자동 반영하지 않습니다. 비회원 제보는 로그인을 안내하고 비회원 즐겨찾기는 해당 브라우저에 보관합니다.

음식물류는 공식 지역 안내에서 확인한 일부 품목만 지원하며, 지역 수거 방식과 단단한 수거 제외 물질을 별도로 확인합니다. 규칙 실행 검증과 실제 지역별 배출 정확성은 구분합니다. 점검 내용·수정 파일·검증 한계는 [전체 개선 보고서](docs/quality-review-2026-10-26.md)를 참고하세요.

이메일·비밀번호 회원가입, 이메일 인증 후 복귀, 로그인·로그아웃, 새로고침 시 세션 복원과 자동 갱신을 Supabase Auth로 처리합니다. 닉네임은 사용자 메타데이터에 저장합니다. 이전 브라우저 테스트 계정은 사용할 수 없으며 새로 가입해야 합니다. 아래 2·3회차의 테스트 인증 설명은 개발 이력입니다.

연결 정보는 `src/services/supabase.js`의 Project URL과 Publishable key입니다. 공개 키는 브라우저용이며 DB 비밀번호·Secret·service_role 키를 넣으면 안 됩니다. 별도 빌드 없이 고정 버전 `@supabase/supabase-js@2.118.0`을 jsDelivr ES 모듈로 불러오므로 인터넷 연결이 필요합니다. `.env` 파일은 자동으로 읽지 않습니다.

**Supabase 대시보드에서 Authentication → URL Configuration의 Site URL을 `https://recyclehelper.vercel.app`으로, Redirect URLs에 `https://recyclehelper.vercel.app/`을 등록하세요.** 로컬 개발용으로 `http://127.0.0.1:5173/`도 Redirect URLs에 추가할 수 있습니다. Email 로그인과 신규 가입을 허용하고 이메일 인증을 활성화합니다. SMTP 기본 발송 제한으로 일반 이메일에 발송되지 않으면 Custom SMTP를 설정해야 합니다.

가입 후 인증 메일은 가입했던 브라우저와 같은 주소에서 여세요. PKCE 검증 정보가 해당 브라우저 저장소에 있으므로 다른 기기에서 인증한 경우 원래 화면으로 돌아와 로그인해야 합니다. 로그인 세션은 Supabase SDK가 브라우저에 보관하며 로그아웃은 현재 브라우저의 세션을 해제합니다.

로그인한 회원의 입력 조건·부속품 정보·판별 결과·분리배출 기록은 Supabase DB에 저장합니다. 최근 목록과 검색·페이지 이동은 DB 기록을 사용하고, 유형별 통계는 DB 함수에서 전체 기록을 집계합니다. 품목 추천과 자동 입력·판별용 품목 사전은 DB의 공개 품목 테이블에서 불러옵니다. 오염·결합 여부에 따른 판별 로직 자체는 기존 JavaScript 규칙을 유지합니다.

**최초 1회 [DB 설정 SQL](supabase/setup.sql)을 Supabase SQL Editor에서 실행해야 합니다.** 사용자별 RLS와 품목 초기 데이터도 포함합니다. 자세한 실행·검증 절차는 [DB 연결 안내](docs/database-setup.md)를 참고하세요. 비회원 기록은 기존처럼 브라우저에만 저장됩니다. 현재 Supabase 회원 ID로 저장된 이전 브라우저 기록은 중복 없이 DB로 이전하며, 공개 데모 계정이나 비회원의 기록을 다른 회원에게 자동 할당하지 않습니다.

테스트 전 `npm install`을 실행한 뒤 `npm test`를 사용하세요. 개발용 PGlite로 SQL을 실제 PostgreSQL 엔진에서 실행하고, 회원 간 접근 차단·통계·이전과 삭제를 검증합니다. 브라우저 앱은 이 패키지를 사용하지 않습니다. 품목 초기 데이터 SQL은 `node scripts/build-database-setup.js`로 다시 생성할 수 있습니다.

대시보드 설정과 수동 검증 순서는 [Supabase 연결 안내](docs/supabase-setup.md)를 참고하세요.

## 2회차 구현 범위 (개발 이력)

- 메인: 서비스 소개, 이용 단계, 준비 중인 기능 안내.
- 로그인: 입력 검증 후 테스트 회원의 이메일·비밀번호와 비교하여 성공 시 메인 화면으로 이동, 실패 시 오류 안내.
- 회원가입: 닉네임 2~20자, 이메일, 비밀번호 8자 이상 및 확인 값 검증.
- 공통 헤더·푸터, 반응형 스타일, 키보드 포커스, 입력 오류 안내.
- 해시 기반 화면 전환: `#/`, `#/login`, `#/signup`, `#/item-input`. 새로고침과 뒤로 가기를 지원합니다.
- 메인의 ‘분리배출 알아보기’에서 물건 및 상태 입력 화면으로 이동합니다. 물건 이름, 주요 재질, 오염·세척·결합 여부와 결합된 재질의 분리 가능 여부를 입력하고 내용을 확인·수정할 수 있습니다.
- 입력 내용을 확인하면 물건 이름이 브라우저에 저장되고 옆의 ‘최근 분리배출한 물품’ 목록에 표시됩니다. 최근 8개의 고유 이름을 보여주며 같은 이름을 다시 입력하면 맨 위로 이동합니다. 로그인한 회원과 비회원의 목록은 별도로 저장합니다. 이 목록은 입력 기록으로, 배출 완료나 배출 방법 판별을 의미하지 않습니다.

테스트 계정은 `demo@example.com` / `recycle1234`입니다. 이메일은 앞뒤 공백과 대소문자를 정리해 비교하고 비밀번호는 정확히 일치해야 합니다. 성공하면 메인 화면과 헤더에 테스트 로그인 상태를 표시합니다. `sessionStorage`에 테스트 회원 ID만 저장해 같은 탭에서 새로고침해도 유지하며, 로그아웃하면 삭제합니다. 저장소가 차단된 환경에서는 현재 페이지의 메모리에서만 유지합니다.

테스트 회원은 `src/services/auth.js`에 정의된 공개 예시입니다. 서버 계정 생성, 서버 인증, API, 데이터베이스는 구현하지 않았으며 이 로그인 상태는 접근 권한을 보호하지 않습니다. 입력한 비밀번호는 저장하거나 전송하지 않습니다. 회원가입 시 브라우저 localStorage에 닉네임, 이메일, 회원 ID, 무작위 salt와 PBKDF2 비밀번호 검증값을 저장합니다. 비밀번호 원문은 저장하지 않습니다. 가입 완료 후 로그인 화면으로 이동하며 등록한 계정으로 로그인할 수 있습니다. 이메일 중복을 거절하고 저장 실패 시 가입 완료로 안내하지 않습니다. 계정은 같은 브라우저·같은 주소에서 유지되며 브라우저 데이터를 삭제하면 사라집니다. 다른 기기에는 공유되지 않습니다. 물건 입력 화면은 구현했습니다. 입력 초안은 현재 페이지와 메인 화면을 오가는 동안 유지되며 새로고침하면 초기화됩니다. 분리배출 방법 판별, 기록·통계는 다음 구현 대상입니다. 글꼴은 Google Fonts를 사용하며 연결할 수 없으면 시스템 글꼴로 표시합니다.

전체 로직 검증: `npm test`

## 3회차 구현 범위 (현재 동작)

- 물품 이름 일부를 입력하면 최대 6개의 후보를 추천합니다. 클릭·터치·방향키와 Enter로 선택할 수 있고, 기존 자동 입력 체크를 켜면 명확한 품목의 재질 정보를 채웁니다.
- 미등록 이름, 이름·재질·세부 종류 충돌, 위험 품목은 본체와 부속품의 확정 안내를 보류합니다. 사전에 모든 물품이 등록되어 있지는 않으며, 추천이 실제 물품과 일치하는지 확인해야 합니다.

- 메인/상단 메뉴의 ‘기록 및 통계’에서 전체 기록 조회, 이름 검색, 개별 삭제, 당시 조건·결과·이유 확인을 제공합니다. 전체 기록은 앞으로 8개 제한 없이 저장하며 입력 화면의 최근 목록만 8개를 표시합니다.
- 통계는 저장된 판별 기록의 총개수, 유형별 개수·비율과 막대그래프를 표시하며 기록 추가/삭제 시 다시 집계합니다. 회원별·비회원별로 구분하고, 판별 결과 없는 이전 이름 기록은 통계에서 제외합니다.

- ‘물건 정보 자동 입력’ 체크 시 명확한 품목명의 재질·종류를 채웁니다. 우유팩/두유팩은 종이팩, 생수병은 페트병을 선택하며 생수병 색상·용도는 직접 확인합니다. 오염·세척·결합 여부는 자동 추정하지 않습니다.

- 플라스틱, 페트병, 종이, 유리병, 금속캔, 비닐, 스티로폼의 주요 일반 수거 대상에 대한 규칙 기반 판별.
- 재질별 세부 종류 질문, 현재 오염이 있을 때만 세척·오염 제거 가능 여부 질문. 일반 종이는 세척 여부를 묻지 않습니다.
- 다른 재질이 결합되었을 때만 분리 가능 여부 질문. 분리 가능하면 최대 5개의 부속품 재질 묶음을 추가하고 각각 상태를 판별합니다. 부속품 자체가 복합재질이면 기타/모르겠어요로 추가 확인을 요청할 수 있습니다.
- 결과에 배출 방법, 사전 처리, 판단 이유, 재질별 안내, 입력 조건, 기준 출처와 확인일을 표시합니다. 특수 품목과 불명확한 답변은 추가 확인으로 안내합니다.
- 전체 판별 결과를 입력 조건·결과·시각·규칙 버전과 함께 localStorage에 보관하며, 입력 화면에서는 최근 8개를 표시합니다. 동일 이름도 각각의 판별 기록으로 남습니다. 목록을 누르면 당시 결과를 조회하고 입력 화면에서는 조건을 복원해 다시 판별할 수 있습니다.
- 기존 v1 이름 목록은 지우지 않고 결과 없는 이전 기록으로 표시합니다. 기존 인증 기능과 회원별/비회원별 저장 구분을 유지합니다.
- Supabase와 외부 API는 연결하지 않았습니다. `src/services/disposal-history.js`의 비동기 저장소 인터페이스를 다음 회차의 DB 저장소로 교체할 수 있습니다.

위 2회차 설명은 개발 이력이며, 판별·최근 결과 조회·통계는 현재 지원합니다. 입력 초안은 새로고침하면 초기화되지만 저장된 판별 기록은 유지됩니다. 지역별 자동 판별은 아직 지원하지 않습니다. 배출 완료 기록을 의미하지 않습니다.

판별 순서, 예시, 데이터 구조와 다음 회차 연결 사항은 [판별 설계](docs/disposal-rules.md)를 참고하세요.

진입점은 `index.html`과 `src/app.js`입니다. 화면 코드는 기존 `src/pages` 하위에, 공통 화면 틀은 `src/layouts`, 폼 UI는 `src/components`, 입력 검증은 `src/utils`, 스타일은 `src/styles`에 배치했습니다. `scripts/serve.js`는 로컬 개발용 정적 서버입니다.

## 프로젝트 구조

```text
recycling-helper/
├── docs/                  # 요구사항과 향후 설계 문서
├── public/
│   ├── images/            # 정적 이미지
│   └── icons/             # 정적 아이콘
└── src/
    ├── pages/
    │   ├── login/         # 로그인
    │   ├── signup/        # 회원가입
    │   ├── main/          # 메인
    │   ├── item-input/    # 물건 및 상태 입력
    │   ├── result/        # 판별 결과
    │   ├── history/       # 나의 기록
    │   └── statistics/    # 나의 통계
    ├── components/        # 여러 화면에서 사용하는 UI
    ├── layouts/           # 공통 화면 틀
    ├── styles/            # 공통 스타일
    ├── services/          # 외부 API 및 데이터 접근
    ├── domain/
    │   └── disposal/      # 분리배출 판단 규칙과 처리 과정
    ├── types/             # 공통 데이터 구조
    └── utils/             # 범용 보조 함수
```

빈 폴더의 `.gitkeep`은 Git에 폴더를 보존하기 위한 파일입니다. 실제 코드를 추가할 때 제거해도 됩니다.

화면 폴더는 역할을 구분하기 위한 구조입니다. 기록과 통계는 필요하면 하나의 화면으로 묶을 수 있습니다. 백엔드와 데이터베이스 구조는 기술 스택 결정 후 추가합니다.

서비스 범위와 검토 사항은 [요구사항](docs/requirements.md)에 정리했습니다.
